# 数据资产管理系统操作流程与数据关联分析

> 分析版本：基于 src/ 当前代码结构  
> 涵盖范围：数据上报系统 → 上报审批系统 → 数据集管理系统 → 数据编目系统 → 数据可视化系统 → 权限管理系统

---

## 一、系统总览

本系统面向武邑县政务数据资产的全生命周期管理，共涉及 **6 个子系统**，覆盖 **6 个政府部门**（行政审批局、卫健局、税务局、发改局、教育局、公安局）。各系统以「部门」为主线进行数据隔离与业务拆分。

```
┌──────────────────────────────────────────────────────────────────────┐
│                        数据资产管理系统                               │
│                                                                      │
│  ┌────────────┐    ┌────────────┐    ┌────────────┐                │
│  │ 数据上报系统 │───▶│ 上报审批系统 │───▶│ 数据集管理系统│                │
│  │  Report.vue │    │DataApproval│    │ DataStore.vue│              │
│  └────────────┘    └────────────┘    └────────────┘                │
│                                              │                       │
│                                              ▼                       │
│  ┌────────────┐    ┌────────────┐    ┌────────────┐                │
│  │ 权限管理系统 │◀───│数据可视化系统│◀───│ 数据编目系统 │                │
│  │DataPermission│    │DataShare.vue│   │  Catalog.vue │               │
│  └────────────┘    └────────────┘    └────────────┘                │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

## 二、各系统功能定义

### 2.1 数据上报系统（Report.vue）

**定位：** 数据入口，各部门向上级填报数据的发起端。

**核心功能：**
- 按部门切换视角，展示该部门所有待上报/已上报任务
- 每个部门维护一个 `tasks[]` 列表（待上报）和 `records[]` 列表（已上报记录）
- 任务状态：`已上报` / `待上报`
- 每条记录包含：任务名称、类型（月度/季度/年度/周度/日度）、截止日期、当前状态、上报人、提交时间、记录数

**关键数据字段（reportDepartments）：**
| 字段 | 说明 |
|------|------|
| `id` | 部门唯一标识 |
| `name` | 部门中文名 |
| `code` | 部门代码（如 ASA、WJW） |
| `tasks[].name` | 任务/报表名称 |
| `tasks[].type` | 报表类型 |
| `tasks[].status` | 已上报 / 待上报 |
| `tasks[].submitter` | 上报人 |
| `tasks[].records` | 记录条数 |
| `records[].fileName` | 上报文件名 |
| `records[].status` | 通过 / 驳回 |

---

### 2.2 上报审批系统（DataApproval.vue）

**定位：** 数据质量把关层，管理员对各部门上报数据进行审核。

**核心功能：**
- 以「部门」为单位管理待审批队列
- `pendingList[]`：该部门当前所有待审批项，每项包含紧急程度（常规/紧急/逾期）
- `history[]`：该部门历史审批记录，含审批结果、审批人、审批时间
- 审批操作：通过 → 数据流转至数据集管理系统；驳回 → 返回上报方

**关键数据字段（approvalDepartments）：**
| 字段 | 说明 |
|------|------|
| `pendingList[].id` | 审批单编号（如 AP-202607-001） |
| `pendingList[].fileName` | 申报文件名 |
| `pendingList[].category` | 业务分类（对应编目主题） |
| `pendingList[].records` | 记录条数 |
| `pendingList[].urgency` | 紧急程度 |
| `pendingList[].deadline` | 截止日期 |
| `pendingList[].submitter` | 上报人 |
| `pendingList[].submittedAt` | 上报时间 |
| `history[].result` | 通过 / 驳回 |
| `history[].approver` | 审批人 |
| `history[].approvedAt` | 审批时间 |

---

### 2.3 数据集管理系统（DataStore.vue）

**定位：** 数据资产沉淀层，审批通过的数据正式归档存储。

**核心功能：**
- 审批通过的数据自动归档至本部门的数据资产库
- 每条归档记录包含完整生命周期追溯：上报人 → 审批人 → 归档时间 → 存储位置
- 按「部门 → 主题 → 数据项」三级分类结构管理
- 统计维度：总存储量、总记录数、总大小、最新更新日期

**关键数据字段（storeDepartments）：**
| 字段 | 说明 |
|------|------|
| `stats.totalStores` | 归档记录总数 |
| `stats.totalRecords` | 累计记录条数 |
| `stats.totalSize` | 累计存储大小 |
| `stats.latestUpdate` | 最近更新日期 |
| `records[].id` | 归档编号（如 ASA-202607-001） |
| `records[].topicId` | 所属主题ID（关联编目） |
| `records[].submitter` | 上报人 |
| `records[].approver` | 审批人 |
| `records[].storedAt` | 归档时间 |
| `records[].remark` | 归档备注（来源说明） |

---

### 2.4 数据编目系统（Catalog.vue）

**定位：** 数据资产目录层，对已归档数据建立元数据目录和分类体系。

**核心功能：**
- 构建「部门 → 业务主题（二级分类）→ 具体数据项（三级）」三级目录体系
- 每个数据项有标准编码（如 ASA-01-01）、描述、状态（已启用/草稿）
- 主题分类覆盖各部门核心业务（如行政审批局有：投资项目审批、市场服务审批、社会事务审批等6大主题）
- 数据项状态管理：已启用 / 草稿

**关键数据字段（catalogDepartments）：**
| 字段 | 说明 |
|------|------|
| `topics[].id` | 主题ID |
| `topics[].name` | 主题名称 |
| `topics[].items[].id` | 数据项ID |
| `topics[].items[].code` | 标准编码（如 WJW-02-01） |
| `topics[].items[].name` | 数据项名称 |
| `topics[].items[].desc` | 数据项描述 |
| `topics[].items[].status` | 已启用 / 草稿 |

---

### 2.5 数据可视化系统（DataShare.vue）

**定位：** 数据价值呈现层，提供数据资产的多维度可视化分析。

**核心功能：**
- 雷达图：数据量、质量、时效性、覆盖率、使用频率、应用价值 6 维评估
- 桑基图：数据从源头到应用端的流转路径（如：窗口受理→审批办理→结果反馈→企业开办）
- 趋势图：各月使用次数/下载量趋势
- 知识图谱：部门-主题-事项-关联部门的实体关系网络
- 热门数据排行：按使用量排名的数据资产
- 应用场景卡片：每个主题下的典型业务场景

**关键数据字段（departmentConfig）：**
| 字段 | 说明 |
|------|------|
| `radar.data[]` | 6 维评分 |
| `sankey.links[]` | 数据流转关系（source, target, value） |
| `trend[]` | 月度使用趋势 |
| `knowledge.nodes[]` | 知识图谱节点 |
| `knowledge.links[]` | 知识图谱关系 |
| `hotData[]` | 热门数据排行 |
| `scenes[]` | 业务场景 |
| `topicData[id].radar` | 各主题独立雷达图 |

---

### 2.6 权限管理系统（DataPermission.vue）

**定位：** 访问控制层，基于系统和部门构建权限矩阵。

**核心功能：**
- 以「系统模块 × 部门」构建二维权限矩阵
- 7 个系统模块：应用管理、上报审批、权限管理、数据上报系统、数据集管理系统、数据可视化系统、数据编目系统
- 6 个部门：行政审批局、卫健局、税务局、发改局、教育局、公安局
- 支持按部门配置其可访问的系统模块范围

**关键数据字段（permissionConfig）：**
| 字段 | 说明 |
|------|------|
| `ALL_SYSTEMS[]` | 系统模块列表 |
| `ALL_DEPARTMENTS[]` | 部门列表 |
| `permissions[].system` | 系统名称 |
| `permissions[].departments[]` | 有权限的部门列表 |

### 3.2 各系统详细操作流程

#### 流程 A：数据上报（上报人视角）

```
1. 登录系统，进入「数据上报系统」
2. 在左侧部门列表中选择所在部门
3. 查看「待上报任务」列表
4. 选择任务，填写/导入报表数据
5. 提交上报 → 状态变为「已上报」
6. 查看「已上报记录」了解审批进度
```

#### 流程 B：数据审批（管理员视角）

```
1. 登录系统，进入「上报审批系统」
2. 在左侧选择要审批的部门
3. 查看该部门「待审批」列表
4. 根据紧急程度优先处理
5. 逐项审核：
   - 审核通过 → 填写审批意见 → 点击「通过」
     → 数据流转至数据集管理系统
   - 审核不通过 → 填写驳回原因 → 点击「驳回」
     → 数据打回上报人
6. 所有操作记录保存至「审批历史」
```

#### 流程 C：数据归档（系统自动 + 管理员确认）

```
1. 审批通过后，数据自动写入数据集管理系统
2. 系统生成归档编号（如 ASA-202607-001）
3. 记录完整来源信息：
   - 上报人、审批人
   - 上报时间、审批时间、归档时间
   - 所属主题（topicId）
   - 备注（报表类型、来源说明）
4. 更新该部门存储统计（totalRecords、totalSize、latestUpdate）
```

#### 流程 D：数据编目（元数据维护）

```
1. 进入「数据编目系统」
2. 选择部门 → 查看该部门主题分类
3. 可对数据项进行：
   - 新增数据项（草稿状态）
   - 编辑数据项信息（编码、名称、描述）
   - 启用/停用数据项
   - 批量导入数据项
4. 数据项与数据集记录通过 topicId 关联
```

#### 流程 E：数据可视化查看

```
1. 进入「数据可视化系统」
2. 查看全局总览：
   - 各部门资产总量雷达图
   - 数据流转桑基图
   - 月度使用趋势折线图
   - 知识图谱网络
3. 选择具体部门深入查看：
   - 该部门 6 维度评分
   - 各主题独立分析
   - 热门数据排行
   - 业务场景详情
```

#### 流程 F：权限配置

```
1. 进入「权限管理系统」
2. 选择要配置的角色/部门
3. 在权限矩阵中勾选该部门可访问的系统模块
4. 保存配置
5. 用户下次登录时根据权限展示对应的菜单和功能
```

└─────────────────┘       │ - status        │       │ - topicId (FK)  │
        │                │ - submitter     │       │ - result        │
        │                │ - records       │       │ - approver      │
        │                └─────────────────┘       │ - approvedAt     │

### 4.2 跨系统数据关联映射

| 关联维度 | 上游 | 下游 | 关联字段 |
|---------|------|------|---------|
| 部门一致性 | 所有系统 | 所有系统 | `dept.id` / `dept.code` |
| 任务追溯 | 上报系统 `tasks[]` | 审批系统 `pendingList[]` | `fileName` / `submitter` |
| 审批归档 | 审批系统 `pendingList[]` | 数据集系统 `records[]` | 审批通过后自动创建 + `topicId` |
| 主题分类 | 编目系统 `topics[].items[]` | 数据集系统 `records[].topicId` | `topicId` |
| 编目细化 | 编目系统 `CatalogItem` | 可视化系统 `topicData[id]` | `id` / topicKey |
| 权限隔离 | 权限系统 `permissions[]` | 所有业务系统 | `system` + `departments[]` |
| 紧急调度 | 上报系统 `tasks[].urgency` | 审批系统 `pendingList[].urgency` | 并行同步 |

### 4.3 关键 ID 编码规则

| 编码类型 | 格式示例 | 生成规则 |
|---------|---------|---------|
| 审批单编号 | `AP-202607-001` | AP + 年月 + 序号 |
| 归档记录编号 | `ASA-202607-001` | 部门代码 + 年月 + 序号 |
| 编目数据项编码 | `ASA-01-01` | 部门代码-主题序号-数据项序号 |
| 部门代码 | ASA / WJW / SWJ / FGJ / JYJ / GAJ | 部门英文缩写 |

## 六、数据流转关键控制点

### 6.1 质量控制
- **审批层**：通过/驳回二级审查，驳回原因可追溯
- **归档层**：自动生成归档编号，防止重复归档
- **编目层**：数据项有启用/草稿状态，新数据须审核后启用

### 6.2 安全控制
- **权限矩阵**：`系统模块 × 部门` 二维控制，精确到部门级别
- **路由守卫**：所有业务路由需登录态（token 校验）
- **数据隔离**：各部门数据严格按 `deptId` 隔离

### 6.3 可追溯控制
- 每条归档记录保存完整链路：`submitter → approver → storedAt → topicId`
- 审批历史永久留存，含审批人、审批时间、结果
